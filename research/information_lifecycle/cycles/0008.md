## Findings

A matching durable log horizon does not establish that two workers used the same live
observations. The negative control switches from mean 2, variance 1/4 to mean 10/3,
variance 1/3 at failover while both advertise horizon {D:1}. There was no new acquisition;
the input set changed. A replacement may legitimately start a different dataset under
another contract, but cannot silently claim to have reproduced the requested result.

A checkpoint bound to its exact input manifest, plus authorized replay of missing
inputs, is sufficient for this additive scalar model. It avoids double counting and
can preserve availability when a base record's raw copy is temporarily unreachable.
Raw replay is also correct when complete. Both report missing coverage rather than
advertising a partial result as complete. All 4,608 combined event checks for these
two methods match the reference when available and avoid forbidden processing.

The tradeoff is selective withdrawal. A mixed checkpoint must be discarded when one
of its inputs loses inference permission under this fixture's P3. Its manifest names
the surviving inputs but does not contain their missing values. Even with a complete
archive, rebuilding can briefly interrupt a checkpoint-based worker while a worker
retaining raw components stays available. Authorized memory can avoid repeating this
work; retaining only the compact aggregate is not automatically the best choice.

Seeding with the old output and replaying its inputs as independent evidence produces
false precision despite duplicate suppression within replay. Conversely, the output's
mean and variance CAN be sufficient restart statistics here when explicitly bound to
the correct model and manifest, with overlap accounted for. The conclusion is not
that an output can never be a checkpoint. Publication alone does not establish the
necessary recovery contract.

These are exact-model findings and bounded event-test evidence, not production recovery
or physical-safety guarantees. No new architectural contradiction was established.
The results strengthen T01 and the already stated retained-state recovery requirement.

## Model and reproducible reference

One static dimensionless scalar x, independent Gaussian likelihoods and a flat prior.
The contrast fixture's values are d=0, a1=2, a2=10, b1=-4, b2=8, b3=-6; an equal-value
fixture sets all values to zero. Variance(d)=1; each A variance is Va and each B variance
is Vb, independently selected from {1,4}. The oracle normalizes inverse-variance weights
over unique, requested, currently permitted source identities. Candidates sum information
pairs H=sum(1/variance), eta=sum(value/variance). Equality is exact using Fraction.

The old worker checkpoint represents C={d,a1,b1}. Its final output represents
S={d,a1,b1,a2}. The standby received {d,a1,b2}. Both have the same durable log horizon
{D:1}, because d is the only log observation. The others are independently identified
application records delivered through a lossy live path; no reliable feed sequence or
automatic feed replay guarantee is assumed. Their authorized archival copies are a
separate fixture facility.

The checkpoint stores (H,eta) and a manifest of immutable IDs and content hashes, bound
to a model/configuration name and a checkpoint digest. The recovery target has a separate
exact manifest identifying S, later extended with b3. These are compute-authorized
recovery metadata, not provenance exposed to every ordinary output reader. The experiment
trusts origin identity, metadata completeness and snapshot production. Hash checks detect
a mismatched supplied snapshot; they do not prove mathematical sufficiency, authorization,
atomic persistence or resistance to a malicious producer.

The independent evaluator reconstructs the candidate's H and eta from recorded original-
input coefficients at every event and asserts agreement with its numerical state. These
diagnostic coefficients are not used for candidate admission or numerical fusion. The
candidate receives only its declared checkpoint/output, target metadata, warm observations,
current policy and delivered records; it cannot read absent raw values from the oracle.
The harness retains historical source values for audit; no physical erasure is claimed.

## Recovery, retention and permissions

At failover, the old worker and producer A disappear. M1 remains reachable and retains
all initial records, all except a1, or all except a2. Its acknowledgments name the exact
record hash, origin and custodian; the missing record receives no M1 acknowledgment.
M2 has that record but is unreachable until event 9. B stays active and acquires b3 at
event 7. Replayed A records keep origin A; a new route does not create a new observation.
This is an explicit reachability schedule, not a proof that a custody acknowledgment
ensures future access under arbitrary faults.

P3 withdraws b1 before restart, during replay, after replay, or not at those stages.
Every run later withdraws a2. Rights to raw replay, checkpoints, recovery metadata and
inference are explicit inputs; effective, learned and enforced policy events coincide.
The accepted methods remove forbidden contributions before further numerical use.
The mixed checkpoint cannot be repaired by reading and subtracting a now-forbidden
raw b1. This fixture has no prior permission to retain a separately canceled residual.
Other explicitly authorized derivative policies require their own cases.

Twelve query states per run:

| Event | Action |
|---:|---|
| 0 | Old result on S, common pre-failover endpoint |
| 1 | Replacement starts; optional pre-restart b1 withdrawal |
| 2 | First half of M1 replay, including a duplicate |
| 3 | Optional during-replay b1 withdrawal |
| 4 | Second half of M1 replay, including a duplicate |
| 5 | Optional after-replay b1 withdrawal |
| 6 | Retry M1 replay under current policy |
| 7 | Acquire, authorize and deliver b3; extend target manifest |
| 8 | Duplicate b3 and retry archive, no new acquisition |
| 9 | M2 becomes reachable and supplies missing record, or a duplicate |
| 10 | Withdraw a2 immediately |
| 11 | Replay remaining permitted evidence, including duplicates |

Two value fixtures, four variance pairs, three archive cases, four b1-withdrawal
schedules and two replay orders yield 192 configurations per method, 960 runs and
11,520 query outcomes. Replay order can alter intermediate availability; settled
answers and input coefficients at events 6, 9, 10 and 11 are invariant to it.

## Methods and measured outcomes

`manifest_checkpoint` keeps C as one aggregate, skips replay already covered by C,
and admits only independent missing target records. P3 invalidates the whole aggregate
if necessary; it rebuilds from lawful records. `raw_replay` starts empty and deduplicates
the requested permitted raw set. Neither publishes until it has complete requested
coverage. These are two supported strategies, not a claim that either dominates.

The negative `horizon_warm` method accepts its unequal warm state because log horizons
match and does not request the missing live history. It respects current permissions
but falsely presents its different dataset as recovery of S. `output_seed` uses the old
output as initial information, then adds replay without excluding the seed's inputs;
it does respect P3 and deduplicates replay records. `hold_output` simply repeats the old
answer through new data and revocation. Its continuity must not make it pass. All methods
get the same scripted replay opportunities; the horizon control declines them. Request
transport, scheduling and network transfer cost are not simulated.

Each method has 2,304 outcomes, including 192 common old-worker endpoints. Counts may
overlap and are fixed-suite counts, not probabilities.

| Method | Available | Wrong mean or variance | Wrong requested coverage | Recounted influence | Forbidden processing/output |
|---|---:|---:|---:|---:|---:|
| Manifest-bound checkpoint | 1,216 | 0 | 0 | 0 | 0 |
| Raw replay | 1,088 | 0 | 0 | 0 | 0 |
| Match horizon, use warm state | 2,304 | 1,812 | 2,112 | 0 | 0 |
| Output plus overlapping replay | 1,664 | 576 | 0 | 576 | 0 |
| Keep old output | 2,304 | 1,296 | 1,536 | 0 | 1,392 |

The first two deliberately withhold incomplete results in 1,088 and 1,216 states.
The reference has access to the stipulated requested values for verification; that
does not grant the candidate those missing values or make the outage an arithmetic bug.
All five use the correct scalar formula on their actual information; failures arise
from coverage, permissions or repeated contributions. Equal-value fixtures ensure mean
agreement alone cannot hide false precision or a different requested input set. In
some equal-value cases even mean AND variance match while the input manifest is wrong.

At event 6, checkpoint recovery is available in 80/192 configurations; raw replay in
64/192. Both recover in all 192 by event 9 and remain correct through final withdrawal.
With complete M1 retention both can reconstruct after retry. With missing a1, only the
still-permitted checkpoint can bridge the gap; after b1 withdrawal it too needs a1.
With missing a2, neither can finish the requested recovery until M2 arrives.

An additional checked witness uses complete M1 retention and b1 withdrawal after the
first complete replay. The checkpoint worker previously skipped copies covered by C.
At event 5 it discards C and lacks d,a1 until retry at event 6. The raw worker already
has those independent components and immediately answers mean 4, variance 1/3. Thus
the aggregate's smaller active numerical state can trade away withdrawal responsiveness even
without permanent data loss. One logical event of outage is not a measured time bound.

## Corrections and dynamic interpretation

For unit variances without early b1 withdrawal, the output-seed control returns mean 2,
variance 1/8 after replay; the correct result is mean 2, variance 1/4. Its replay IDs
are unique, but each observation is represented twice across seed and replay. A real
new b3 should move the mean from 2 to 2/5, a correction of -8/5. The bad control moves
to 10/9, only -8/9, because it invented precision. Repeated delivery then leaves it steady
and wrong. This is a recovery-specific route to the slow correction response seen in
cycle 0006's feedback study.

Holding the old result gives total variation zero, including when its input becomes
forbidden and when b3 arrives. That is a failing control. Correct methods instead
surface an explicit availability gap and accept a justified changed answer as soon
as the required lawful information is available. Adjacent-valid mean jumps and total
variation are stored, but gaps make jumps undefined; lower variation is not treated
as better by itself. New-data counts refer to acquisition, not newly delivered archival
evidence: recovery of older evidence can legitimately change an answer without a new
acquisition. No smoothing, controller, obstacle or physical plant is part of this slice.

A targeted positive test binds the final output's own mean/variance to S as an explicit
checkpoint, skips overlapping replay, and incorporates b3 exactly. This prevents the
overly broad conclusion that published numbers are inherently unsuitable for restart.
For more general estimators, a displayed marginal need not contain the needed joint
state, linearization, calibration or decomposition; this scalar witness does not supply it.

## Design implications, limits and next action

For Nestbox, a recovery contract must identify the actual consumed observations and
the sufficient application state, including whatever non-additive models require.
Read-only context was checked at nestbox-ng `041f1146df2e2a271cd0489fda520bc65f2e9f70`:
SUBSTRATE §3.1 L5 describes log horizons, §3.2 F1-F3 makes feeds lossy/non-replayable,
and §7 E6's same-horizon continuity explanation explicitly concerns the same logs.
This experiment does not refute that restricted log-only statement. Extending it to a
solver also consuming unequal live observations would need additional recovery state
or an explicitly changed result/epoch contract. No application code was tested here.

For Soradyne, the current shared-flow contracts already distinguish publication from
restart state, require stated custody coverage and preserve opaque input identity.
This experiment supplies a concrete fixture for that direction. A provider can carry
and retain manifests/checkpoints and enforce grants without knowing their numerical
meaning. An application must say which retained artifacts suffice and when a recovered
result may claim the requested coverage. Output read rights must not imply access to
private recovery metadata or raw history. No new protocol schema is proposed here.

Sufficiency is established only for the stated exact independent scalar model, trusted
consistent snapshots, supplied metadata and immediate policies. These tests do not
cover floating-point or nonlinear restart equivalence, correlated observations, checkpoint
write interruption, distributed fencing, lost acknowledgments, authority lag, replay
deadlines, long-term custody failure or physical safety. First recovered-event metrics
describe the first correct snapshot, not a guarantee that later faults cannot cause an
outage. Full F01/F02 and mandatory F01+S05 remain open.

Next bounded slice: R03+F03, explicit fixed-lag/checkpoint retention expiry followed by
selective withdrawal. Compare retained independent contributions, a mixed summary with
authorized replay, and explicit unsupported/unavailable recovery after required state
expires. Predeclare a small finite retention/time budget and measure what information
and recovery availability each policy loses. Keep atomic-write crash injection and
role fencing queued separately. The existing plan calls for this recovery/retention
work before moving into nonlinear geometry; no new family is being invented.
